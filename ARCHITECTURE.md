# Dovahengine architecture

## Goal

A native engine that plays *The Elder Scrolls V: Skyrim Special Edition*
from the user's own legally owned data files, ending as an Android APK on
Dylan's phone. Clean-room throughout: original code, public format
documentation only, no Bethesda code or assets in the repo.

## Stack

- **Rust**, for the format parsers and engine core. Memory-safe, no
  garbage collector pauses, and it cross-compiles to Android ARM64.
- **Bevy** (from Phase 2) for rendering, ECS, and the game loop. Bevy
  targets desktop and Android from the same codebase.
- One crate per subsystem under `crates/`, so each piece can be built
  and tested on its own.

## Phases

### Phase 1 — Read the game (done)

The engine must understand Bethesda's file formats before it can show
anything. Each format gets its own crate plus a notes file in
`docs/formats/`, and each crate gets tests that run without real game
data (synthetic fixtures), then verification against Dylan's real files.

| Crate (planned) | Format | What it reads |
| --- | --- | --- |
| `dovah-bsa` (done) | BSA v104/v105 | Archive listing + extraction |
| `dovah-esm` (done) | ESM/ESP | Records: cells, NPCs, quests, items |
| `dovah-nif` (done) | NIF | Meshes (NiTriShape / NiTriStrips / BSTriShape, shaders, textures); skinning and animation are future work |
| `dovah-dds` (done) | DDS | Textures: uncompressed RGB(A) + BC1–BC7 decode to RGBA8, mipmaps |
| `dovah-pex` (done) | PEX/PSC | Compiled Papyrus bytecode (.pex) + source (.psc): parse the script, its properties, states, and functions, so Phase 3 can run it |

### Phase 2 — Show the world (current)

Bevy 0.20 renderer (`dovah-app`). Load a cell from the ESM, stream its
meshes and textures out of the BSAs, first-person camera, collision.
Milestone: walk around Riverwood.

### Phase 3 — Play it

Physics, combat, NPC AI, dialogue, quests, Papyrus runtime
integration (the core is done in M7), save/load. This is the long
phase; it lands feature by feature, tested in-game as it goes.

### Phase 4 — Phone

Android packaging: ARM64 build, touch controls, on-screen gamepad,
storage for the user's own data files, performance budget for a
Snapdragon-class phone. The engine is designed from Phase 1 with this
in mind (no desktop-only assumptions, streaming instead of load-all).

## Rules

1. **No Bethesda code, no game assets, ever.** Format knowledge comes
   from public documentation (UESP wiki, NifTools spec, Microsoft
   docs) and from observing files the user owns.
2. **No borrowed engine code.** Not a fork of Mudcrab or OpenMW, and no
   copying their implementations.
3. **Test before claiming.** A milestone is done when its tests pass
   and, where real data is involved, when it has run against Dylan's
   actual files.
4. **Small, verified steps.** One format, one system at a time. A
   working reader beats a grand design doc.
